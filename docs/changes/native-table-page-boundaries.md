# 原生页点的完整表格边界

## Status

implemented

用户已授权继续修复本轮发现的共享兼容缺口。

## Problem

在短双列管道表的单元格中加入完整 pagebreak span，会影响 Pandoc 的列宽推断，将自动列宽改成显式比例。页点不能悄然改变表格布局。现有 native before_target 只接受标题、以标题开头的容器和 Figure，不能表达已核定的完整表格或表组边界。

## Scope

- 复用现有 native-pagebreaks 与 before_target，不增加模式、阅读器扩展或第二份状态机制。
- 允许稳定 ID 指向完整 Table，或第一个有效子对象为 Table 的 section／div 表组。保持原有标题／Figure 调用、默认条件、代码禁区及 ID 唯一性校验。
- 正式底稿可用原生 fenced Div 表达真实表组；页点不进入管道表单元格，规范化时迁到已声明的表／表组前。不增加伪标题、空图注或读者可见空段。
- 原书在同一无正文容器集中多个点时，保其原序和共用边界，不推断成各个表行或不同物理页界。

- 删除迁移后留下的空段时，在原位置保留其 tail 字符与空白；沿用既有空段删除条件，不新增空属性段保留规则。

## Acceptance Criteria

1. 实际 Pandoc 短双列表重现原问题；新承载保完整 Table AST、列宽、单元格内容、链接和样式，只有显式表组身份／页点位置变化。
2. 正式 EPUB 中页点为标准空 span，保原 ID、标签、顺序及唯一 page-list；集中点链、迁移检查和既有标题／Figure 正反例保持有效。
3. 行／单元格、任意非表组 Div、代码内目标、缺失／重复 ID 仍拒绝，不放宽来源绑定或代码行迁移条件。
4. 先运行受影响页导航／实际 writer 回归，冻结后完成最终全项目；不重跑无变化的书籍内容模块。公开 fixture 为合成表，真实书籍与私有证据留本机。

## Result

候选已实现完整 Table／table-leading 表组边界与尾文本保全；保持旧标题／Figure／PDF 调用和既有空段判定。真实 Pandoc 对照中，长行内页点使双列宽从自动变为 0.5／0.5；fenced Div 承载则保完整 Table AST 与最终 XHTML 表格。

受影响的页导航、标题迁移、延后对象及脚注模块为 161 通过、63 项 subtest 通过。变更处未引入 lint；冻结后的全项目为 **919 通过、2 跳过、356 项 subtest 通过**，用时 272.38 秒。两个跳过沿用当前环境的可选公式库／真实浏览器条件；本变更的实际 Pandoc writer 回归已执行。

## Review

独立只读审查发现：迁移页点后删除空段会漏掉 p.tail 正文，页导航 QA 仍可能通过。完整规范化反例确认输入文本出现一次、输出消失；已按实际原因修复，反例重跑恢复一次且全部正文字符保全。主 Agent 复核最小 tail 拼接差异、源点链及完整 Table 回归；普通空段仍按原条件删除，不新增元数据规则。其余目标解析、禁区、显式链和真实 writer 证据复用。
