# 固定公式渲染器的资源上界与失败缓存

## Status

implemented

## Problem

完整构建中长式可能触发原生 dvisvgm 的 20 秒限制，而单对象通过不能证明批量问题消失。固定 GladTeX 3.1.0 无 jobs 选项，按逻辑 CPU 的 2.5 倍建立线程；内部 Popen 未设置 Windows 隐藏标志。

行号 SVG 版本戳只在 Main.run 成功后写入，失败时已生成的正确 SVG 虽经生产 API 检查点保存，却缺戳并在下次重复失效。

## Scope

- 只在 tools/gladtex_filter.py 对固定第三方模块加薄适配，保原转换器、任务取消、异常、缓存和进程通信逻辑，不另造队列、调度器或缓存。
- 线程池上界为 8；不修改 stdlib 模块或全局 CPU 事实，恢复被适配的第三方模块局部名称。不改 Python、LaTeX、dvisvgm flags、20 秒限制、公式或成品样式。
- 内部 Popen 复用已有 hidden_process_options，仅设置无窗口选项，不更改命令、路径或通信。
- 失败后只给当前输入中已经生成、来源匹配且结构有效的行号 SVG 写当前版本戳；补戳时 viewBox 的数值必须有限且宽高为正。缺失对象不伪造成功，保留原失败。成功路径仍要求完整集合，普通缓存的既有合同不变，旧缓存先由原 cache_statistics 剔除过期活动项。
- 修改对应测试和直接机器契约。

## Acceptance Criteria

- 同源五组各 60 个完整 Math，8／16／60 并发的既有 DOE 共 900 转换成功；同组 SVG／alt／style 相同，生产适配不改这些内容。
- 实际池不超过 8，第三方模块和 stdlib 绑定恢复；Windows 子孙进程隐藏，错误与原 20 秒限制保留。
- 部分生成后失败的缓存可复用已成功对象，未生成、过期、结构损坏或 viewBox 非有限／宽高非正的项不被标为当前版本，原异常不被检查点错误覆盖；成功路径和普通缓存的原合同不变。
- 使用新适配对实际冻结输入的完整公式模块运行后，才重试最终全量；不逐式预热或盲重跑整本。

## Result

DOE：8 线程五批平均 19.2498 秒，16 为 16.5344 秒，60 为 17.0562 秒；8 的 dvisvgm 最长 6.297 秒，16／60 分别 12.672／12.985 秒。选择 8，以每批约 2 秒平均吞吐代价换取长式更充足的 20 秒余量。默认 60 五批未复现完整构建失败，根因尚未证实；这是已验证无内容差异的资源策略。

模块局部薄适配已合入，不改第三方转换器或 stdlib；正常、原异常、缺失／坏／越界／非本输入、成功严格路径与真实失败后命中等相关回归 29 项通过，包含真实 EPUB 与 EPUBCheck 接缝。60 个源对象的新适配实际负载峰值为 8，逐对象与既有 8 线程基线 SVG／alt／属性相同。

失败后部分行号 SVG 的补戳增加有限数值与正宽高 viewBox 校验；NaN、inf、非法值及非正宽高的 5 个反例实际通过。该约束只作用于失败后的部分补戳，不改变成功或普通缓存的原合同。

完整公式模块首次触发一个底稿宏冲突而非 20 秒超时，按原生 TeX 纠正后完成模块检查。失败时已成功行号对象补戳，未生成的坏公式未伪成功；生产 API 检查点只重编变更键。完整模块通过 alt／类型／资源／比例和关键原生行号 glyph 检查。公式模块不代替导航／正文／浏览器的最终全量验收。

## Review

核对 DOE、实际适配差异、失败恢复正反回归及正式等价公式模块；独立核查确认过期活动项先剔除，失败仅给本输入实际成功条目补版本，原异常、模块绑定和低并发请求保留。无 blocking，资源策略不冒称已证超时根因。
