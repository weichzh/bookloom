# 书籍转换与翻译工作流

## 适用范围

本文件拥有从来源核定到正式交付的执行顺序。机器字段和格式语义写在 `docs/codebase/CONTRACTS.md`；EPUB 专属生成与验收写在 `docs/workflow/EPUB.md`；单书进度只写在该书 `STATUS.md`。

## 1. 选择正式底稿

先查看来源样本页和最终交付物，再选择：

- 复杂扫描书或高质量固定版式 PDF：Typst。
- 已有 TeX 资产、复杂数学或既定模板：LaTeX。
- 内容优先、HTML/EPUB3 为主要交付物：Pandoc Markdown。
- Web 原生完整文档：HTML。

每种语言只维护一种正式底稿。用户明确不要源语言正式底稿时，目标语言可以是 manifest 中唯一的 `role = "source"`；这只省略源语言文件，不省略原图核对。

## 2. 初始化与来源探针

1. 确认 `Books/` 只有不可修改来源。
2. 对 PDF 用 `mutool info` 检查页数、页面尺寸、加密和元数据；对 EPUB 检查 container、OPF、spine、nav、资源和固定页码能力。
3. 查看封面、书名页、版权页、全部目录页、普通正文、章首页、引文、诗歌、脚注、图表和索引样本。
4. 创建 manifest，登记来源路径、SHA-256、语言、格式和正式输出。
5. PDF 完整建立 `page-map.tsv`；没有可靠固定页码的 EPUB 建立 `source-units.tsv`。
6. 在 `STATUS.md` 登记阶段、待核对范围和已知问题。
7. 按完整章节确定文件边界，不按扫描页拆正式文件。
8. 环境或 manifest 变化时运行一次 `doctor`。

没有理解主要版式前，不批量生成全书正式底稿。

EPUB 初始化使用统一 `init`；无可靠页码时选择 Markdown／HTML 的 source-units 路径。需要辅助恢复时使用 `source-draft`，输出只在 `scratch`，保留原生段落、强调、标题、链接与位置；不得直接据草稿翻译或宣称核定完成。Unsupported 或 ambiguous 项先回到原生 XHTML 和可读渲染裁决，不用临时转换器静默扁平化。

## 3. 查看原页

页面图只渲染到仓库 `.tmp/`。普通页使用足以辨认正文的分辨率；字体细节、公式、表格和疑点再提高分辨率。

逐页检查：

- 每个单词、标点、数字、罗马数字和重音；
- 本页是新段还是上一页续段；
- 斜体、粗体、小型大写、书名和专名；
- 正文、展示引文、诗歌、题记、译文和署名；
- 标题层级；
- 脚注、表格、图像和索引阅读顺序；
- 页眉、页脚和印刷页码是否误入正文。

看不清时扩大原图并结合相邻页。仍不能确定时在 `STATUS.md` 记录疑点，不猜测。

EPUB 视觉证据按来源哈希、spine 单元／XHTML 路径、实际打开 URL、视口及可见首尾锚点登记；截图文件名只作辅助。主 Agent 对照原生单元和实际截图复核边界，无法对应范围的截图不得计入覆盖。源映射绑定原生内容，标记数量和转换成功不能代替逐单元查看。

文本层有用时整本只提取一次。OCR 只处理文本层缺失、阅读顺序冲突、复杂公式或疑点页；两者都只辅助已经查看原图后的定位和校正。

## 4. 恢复语义

标题、强调、引文、脚注、列表、表格和诗行使用正式底稿格式的原生语义；格式对应表见 `CONTRACTS.md`。

以下视觉线索不能单独决定语义：

- 段首引号不等于展示引文；
- 冒号后的长段不自动成为展示引文；
- 大写行不自动成为标题；
- OCR 换行不等于诗行、标题或新段；
- 纸书页界不等于正式底稿分页。

诗歌使用明确诗行语义。题记、译文和署名分别表达，不把署名当标题。只有重复出现且真实降低复杂度的版式才增加共享宏。

图号必须先由原页视觉核定：原书有图号时保留原编号，原书没有图号时不按图片顺序、正文引用或 OCR 结果推断。Pandoc Markdown 的编号图片在替代文本中写出同一图号，并设置稳定的 `{#fig-...}` 标识；连续多图共用图注时按原书顺序一一对应。

## 5. 源页与源单元

溯源标记是元数据，不是结构边界：

- 跨页续段保持一个段落，把标记嵌入句子或段落内部。
- 同一强调、引文、诗歌、脚注、表格或图注跨页时，标记留在同一个语义节点内。
- 标记不能单独占行形成空段，不能放进标题，也不能拆开单词。
- 不按来源页插入强制分页。
- 数量、顺序和唯一性只用于发现漏项，不能证明位置正确。

内容结构完成后，逐个检查标记前后源码和成品，确认没有可见空格、断词、断段或空节点；中文字符两侧不保留分页标记遗留的 ASCII 空格，统一入口会在 EPUB 归一化并报告候选。

PDF 使用连续 `source-page`；没有固定页码的 EPUB 使用连续 `source-unit`。具体语法和表格契约见 `CONTRACTS.md`。

## 6. 斜体与中文概念

每个扫描页中的连续斜体对象，在正式底稿中对应一个连续强调节点。源页标记可以位于节点内，不能把同一对象截断。

中文规则：

- 概念或术语使用格式对应的 `cn-concept`，显示中文译名和原文。
- 书名、报刊名、诗作名或文章名同时显示译名和原名时，放在同一个强调节点内。
- 只译出不保留原文的斜体对象，使用一个强调节点包住中文译文。
- 只保留原文时，使用一个强调节点包住原文。
- 原书罗马体不能因中文书名号或译者偏好擅自增加强调。
- 省略斜体书名的原名必须有术语表或已核定译文依据。

不得把作者名、刊名或纯书目资料机械改成概念节点。

## 7. 分段与协作

- 默认同时最多推进一本书和一个共享变更；共享行为的改动独立按 `docs/workflow/PROTOCOL.md` 管理。
- 优先分配完整章节；章节过长时按约 25--50 页的闭合语义段拆分，公式或图表密集段才缩小。
- 每个负责人独占明确页段和文件或 `.tmp/` 分片，并交付页段、疑点、资产和术语变化。
- 主 Agent 独占 manifest、`STATUS.md`、共享样式、正式入口和最终术语表。
- 合入时重点检查相邻分片首尾、跨页段落、引文、脚注、公式、图表和源页标记。
- 临时分片合入后删除。

并行只改变执行方式，不降低逐页责任和最终验收门槛。

## 8. 翻译

双语路线：

1. 对应源语言章节先完成原图视觉核对。
2. 复制已核定结构翻译。
3. 保持源页、标题、强调、引文、诗歌、脚注、数学、图表和链接一一对应。

仅目标语言路线：

1. 直接依据原图和相邻页建立同等语义结构。
2. OCR、文本层和临时源文不能成为未经核定的中间真相。
3. 每个页段仍审计数字、专名、脚注、图表和边界。

两种路线都先查 `glossary.tsv`，不增加原文没有的解释。译完一章后逐段检查漏译、数字、年代、引文归属和外文原名。

## 9. 目标语言封面

每个目标语言版都必须设计独立封面。封面至少正确呈现该语言的书名、副标题、作者及项目要求的译者或版本信息；不能把含源语言主标题的原封面直接当作目标语言封面。先查看原封面，再按以下二选一判定路线：

1. **参考原设计**：原封面具有可辨认的构图、图像母题、字体层级、色彩系统、时代或系列特征时，提炼这些设计意图，重新排印目标语言信息。参考不等于逐像素复制；没有明确授权时，不直接复用受保护的插画、照片、商标或出版社版式资产。
2. **重新设计**：原封面实质上只是默认模板或书名页式排字，没有有意形成的图像、构图、字体层级、色彩系统或其他视觉识别时，不把它作为设计参照，而是依据全书主题、体裁、时代、目标读者和目标语言书名建立新方案。单纯使用大字号、居中标题、默认字体或代码模板不能单独构成可参考的封面设计。

“极简”不等于“无设计”。只要留白、比例、字形、层级、颜色或材料感经过明确组织，就按“参考原设计”处理；只有看不出这些有意选择时，才判定为“重新设计”。判定结论和理由写入该书 `STATUS.md`。

制作顺序：

1. 写出简短设计要求：主题与读者、必须出现的文字、保留或放弃的原封面特征、构图、色彩、成品比例和禁用元素。
2. 需要原创插画、背景、纹理或视觉概念时，优先考虑 `GPT Image 2`；执行前确认当前环境实际可用的模型。简单的纯排字或几何方案直接用 Typst、LaTeX、SVG 或现有排版工具完成，不为使用模型而生成图片。
3. 生成式图像原则上只生成无文字或极少文字的底图，书名、作者等必须准确的文字由可编辑排版层完成；不得接受模型生成的错字、伪字或不可编辑标题。
4. 最终使用的底图和可编辑封面源文件放入该书 `assets/`；候选图、联系表、放大测试和失败版本只放 `.tmp/`，定稿后删除。
5. manifest 和正式入口必须让每个目标语言成品使用对应封面。若当前 schema 只能共享一个封面而同一工作区需要多个语言封面，在 `STATUS.md` 记为阻塞，并先完成独立的 schema 或构建能力变更；不得静默复用错误语言的封面。

封面验收同时检查缩略图和全尺寸：文字、语言、专名与版本信息准确；层级和对比清楚；无异常肢体、伪字、生成残片、拉伸、裁切或低清晰度；比例适合全部正式输出；PDF 与真实 EPUB 阅读器中的封面均为最终版本。生成工具、最终资产路径、视觉结论和成品哈希写入 `STATUS.md`。

## 10. PDF 版式

先确认内容结构，再从原书恢复：

- 页面尺寸、页边距和版心；
- 正文、引文、诗歌和脚注的字体分工；
- 字号、行距、段距和首行缩进；
- 章号、标题和节标题间距；
- 题记、署名、表格和图注对齐；
- 奇偶页页眉、章首页抑制和页码位置；
- 目录、书签和索引栏数。

成品分页不必逐页复刻来源。不得为对齐来源页破坏自然排版。

标题层级同时驱动目录和 PDF 书签，不维护第二份手写标题列表。标题自定义样式必须保留块级粘连，避免标题孤立页尾。前置罗马页码的逻辑跳号用页码 counter 表达，不插空白页凑物理页数。

## 11. 验证节奏

1. 为冻结范围做一次来源审计；每个分段内部完成逐页原图核对。
2. 每次调用作品 CLI 前，用 `--activity` 声明自上一工站后的来源核对、翻译、结构／样式修复或审校；文件净变化由 CLI 自动记录。
3. 合入后运行 `uv run python tools/translator.py prepare 'Works/<书名>' --activity ...`，由 CLI 依次完成中文 Markdown 的 AutoCorrect、lint 和 `check`；随后只用 `refresh --lang ... --target ...` 检查并重建受影响输出，已变化的单个输出仍完整构建和验收。
4. 全部范围合入后只建立一个终态候选，并执行一轮与初译分开的只读审校。
5. 主 Agent 修复 blocking 问题，只 refresh 受影响目标与必要回归；非阻塞建议不扩张冻结范围。
6. 对最终候选运行一次全量 `finalize`，完成全部 manifest 输出的机械检查、构建和证据生成；PDF 来源页渲染统一使用 `mutool`。
7. 人工内容与视觉验收也通过后，先在 `STATUS.md` 明确写入 `full-local-accepted` 或等价完成声明，再运行 `complete --activity visual-qa`；命令核对当前 final 与全部正式输出，只原子迁移 manifest 状态，不改写人工记录。
8. 紧接着用 `deliver --lang ... --target ... --to ... --activity none` 把唯一正式输出交付到明确目标文件；命令必须绑定当前 `final.json`，并在原子替换前后核验大小与 SHA-256。外部交付继续单独记录，不混入本地完成状态。

局部 proof 用于减少往返，不替代最终检查。`finalize` 也只证明机械链通过，不代替原页、翻译、封面或视觉验收。

## 12. 正式验收

PDF：

- 构建成功并检查页数、书签和链接；
- 把全部正式成品页渲染到 `.tmp/`；
- 联系表逐页检查空白异常、重叠、溢出和分页；
- 封面、前置页、章首页、密集脚注、引文、诗歌、延伸阅读和索引边界高分辨率复看。
- 若本轮替换了已有正式 PDF，还要生成旧页到新页的单调全页映射，列出新增／跳过页和偏移区间。以跨页文本覆盖为主、图像指纹为辅；封面、目录、纯图页和参考文献边界等低文本页必须人工裁决，不能把同页像素差异或固定页码偏移直接判为内容丢失。

EPUB：

- 按 `docs/workflow/EPUB.md` 执行包、语义、公式、导航、资源、EPUBCheck 和 `agent-browser` 浏览器渲染验收。

完成声明还要求：

- 来源纳入范围每页已经视觉核对；
- 正式底稿文字、数字、专名和结构以原图为准；
- 目标语言无漏译；
- 每个目标语言封面已经按本流程设计、集成并完成视觉验收；
- manifest 声明的全部正式输出已重新构建；
- `STATUS.md` 无未解决正文、版式、导航或索引问题；
- `.tmp/` 和书籍目录没有废弃中间产物。

## 13. 状态、交付与清理

`STATUS.md` 按章节或约 25--50 页更新，只写已验证事实。逐页记录按来源页升序维护，不按处理日期堆叠。

状态声明必须区分：

- `legacy-baseline`：历史成品存在，但缺少当前完整证据；
- `scoped-repair-accepted`：本轮冻结范围已修复并验收，未宣称全书重新核定；
- `full-local-accepted`：全书满足当前本地内容、构建和验收门槛；
- external delivery：另行说明外部副本路径与哈希，不把它混入本地完成状态。

不同文件的封装元数据、阅读位置或书签状态等小差异不自动构成内容缺陷；只有正文、结构、导航、资源或可见样式证据表明变化时才扩大修复范围。

`STATUS.md` 记录来源、正式输出的路径与 SHA-256，以及内容和视觉验收结论等耐久事实。`.tmp/` 证据只在文件当前仍存在且任务尚未清理时引用；清理后保留结论和摘要，不再把临时路径写成可用证据位置。

交付前实时确认目标路径，不从旧记录推断 OneDrive 本地化目录。复制后核对文件名、大小和 SHA-256，并把证据等级写清楚。

最后运行：

```shell
uv run python tools/translator.py clean 'Works/<书名>' --activity delivery
```

`clean` 只清理该书在仓库 `.tmp/translator/` 中的诊断目录；其他临时脚本、页面图、解包目录和分片仍由本任务显式删除。
